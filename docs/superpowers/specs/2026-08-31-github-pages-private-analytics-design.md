# GitHub Pages 與隱私優先分析發布設計

## 目標

將「好宅指南｜台中首購適居分析」從 Sites 另行發布到 GitHub Pages，使用不含原 Sites 帳號／工作區命名空間的公開網址 `https://watah-ai.github.io/`。遷移必須保留既有首頁、音樂與自動播放備援、單一捲動、問卷、推薦結果、行情及方法頁功能。

網站上線後可加入 Google Analytics 4（GA4），但在沒有評估 ID 或訪客尚未同意前不得載入或傳送分析資料。任何問卷答案、財務資料、家庭條件及個人化推薦內容皆不得傳送至 GA4。

## 已確認方案

使用 GitHub 使用者首頁儲存庫 `Watah-ai/Watah-ai.github.io`，由 GitHub Actions 建置及發布根路徑網站：

- 儲存庫：`Watah-ai.github.io`
- 正式網址：`https://watah-ai.github.io/`
- 發布來源：GitHub Actions 產生的靜態輸出
- 原 Sites 網站保留，不在本次遷移中刪除或下架，以便發布失敗時仍可回復存取

未採用專案子路徑網址，因為根網址較短、資源路徑較簡單，也最符合降低命名連結的需求。未採用自訂網域，因為使用者目前沒有網域，也不要求完全自訂網址。

## 發布架構

### 靜態輸出

現有網站為純前端單頁應用，市場資料隨程式碼封裝，分析在瀏覽器內完成，不依賴伺服器 API、資料庫、Cookie 或登入狀態。因此 GitHub Pages 版本使用 Next.js 靜態輸出，不引入新的後端服務。

現有 Sites／Vinext 建置維持可用，GitHub Pages 使用獨立的建置入口。GitHub Pages 建置時才啟用靜態輸出，避免破壞目前 Sites 開發與發布流程。

### 自動發布

新增 GitHub Actions 工作流程：

1. 取出 `main` 分支程式碼。
2. 安裝鎖定版本的 Node.js 依賴。
3. 執行 lint、正式建置及靜態輸出。
4. 上傳輸出目錄為 Pages artifact。
5. 只在前述檢查成功後部署至 GitHub Pages。

工作流程採 GitHub 官方 Pages actions，權限限於讀取儲存庫內容、寫入 Pages 及取得部署身分權杖。只有 `main` 分支更新及手動觸發能發布。

## 資源與功能相容性

網站部署在使用者根網址，因此既有 `/moonlight-sonata.mp3`、`/og.png` 與 `/favicon.svg` 根路徑可以保持不變。需在靜態輸出環境驗證：

- 首頁星系背景與響應式版面
- 音樂一秒後自動播放嘗試及首次互動備援
- 音樂控制按鈕
- 首購問卷所有步驟
- 推薦結果與情境調整
- 台中行情及方法資料
- 單一頁面內的畫面切換與捲動重置
- 直接開啟根網址及重新整理

## GA4 隱私設計

### 啟用順序

GitHub Pages 第一次發布時不設定 GA4 評估 ID，因此不得載入 Google Analytics。網站上線後，使用者以正式 GitHub Pages 網址建立 GA4 網站資料串流，取得 `G-XXXXXXXXXX` 評估 ID，再以 GitHub Actions repository variable 提供給建置流程並重新發布。

評估 ID 不是密碼，可出現在前端程式，但仍集中透過建置環境變數管理，避免硬編碼及日後更換困難。

### 同意機制

GA4 採明確同意後才啟用：

- 初次造訪顯示簡短分析選擇介面。
- 選擇「同意匿名分析」後才載入 Google tag 並送出事件。
- 選擇「僅必要功能」時完全不載入 GA。
- 同意選擇可儲存在瀏覽器本機；不得與問卷答案合併。
- 提供可再次變更分析選擇的入口。

在 GA4 管理介面中關閉 Google Signals、廣告個人化及非必要的精細位置／裝置資料收集，並使用可行的最短資料保留期限。

### 允許的資料

GA4 僅記錄匿名、低敏感度的產品使用事件：

- 虛擬頁面瀏覽：首頁、適居分析、分析結果、台中行情、方法與資料
- 流程事件：開始分析、完成分析、查看範例、調整情境
- 基本成效：工作階段、互動時間、流量來源與粗略裝置類別

禁止傳送：

- 頭期款、收入、負債、支出、利率或預算計算結果
- 家庭人數、房間需求、通勤地點或生活偏好
- 推薦區域、房型、外部搜尋字串或任何結果明細
- 姓名、Email、電話、完整 IP、使用者 ID 或其他可識別欄位

### 單頁追蹤

網站畫面由 React 狀態切換，不會自然產生瀏覽器路由事件。因此在畫面狀態變更時手動送出一筆虛擬 `page_view`，並關閉可能造成重複計數的自動頁面瀏覽。事件名稱與參數使用固定白名單，不接受問卷或推薦資料作為動態參數。

## CIA 與安全界線

### 機密性（Confidentiality）

- 網站沒有後端帳號、資料庫或秘密金鑰。
- 問卷答案只存在目前瀏覽器分頁的 `sessionStorage`，不提交 GitHub 或 GA4。
- GA4 未獲同意前不載入；事件參數採白名單。
- 儲存庫公開時，不提交 `.env`、權杖或本機產物。

### 完整性（Integrity）

- `package-lock.json` 鎖定依賴版本，GitHub Actions 使用可重現安裝。
- lint 與建置失敗時停止發布。
- 部署來源限定 `main` 分支，Pages artifact 由工作流程產生。
- 發布後檢查主要資源與互動功能，並確認 GA 未在拒絕／未選擇時送出請求。

### 可用性（Availability）

- GitHub Pages 由靜態檔案提供，不依賴應用伺服器或資料庫。
- 原 Sites 版本在新網站驗證完成前維持可用。
- Git 歷史及 Actions 部署紀錄提供版本回復依據。
- 音樂載入失敗不得阻斷分析功能。

### GitHub Pages 限制

GitHub Pages 不提供專案自訂 HTTP 回應標頭，現有 Sites 版本的 CSP、`X-Frame-Options`、`Permissions-Policy` 等伺服器回應標頭無法原樣轉移。靜態 HTML 可加入相容的 CSP meta 作為部分補償，但 `frame-ancestors` 等指令不能靠 meta 完整取代。

接受此限制的理由是網站沒有登入、後端寫入、付款、機密資料或跨使用者狀態，主要風險面較小。若未來加入帳號、表單上傳或敏感資料服務，必須改用能控制 HTTP 安全標頭的主機，而不能沿用目前的 GitHub Pages 架構。

## 錯誤處理與回復

- GitHub 驗證失效時停止建立遠端儲存庫，要求重新登入，不以其他帳號代替。
- 若 `Watah-ai.github.io` 已存在，先檢查內容及 Pages 狀態，不覆寫不屬於本專案的資料。
- 建置或測試失敗時不推送發布修正，保留本機變更供檢查。
- Pages 部署失敗時查看 Actions 記錄並修正；原 Sites 網站繼續提供服務。
- 沒有 GA4 評估 ID、格式無效或載入失敗時，網站功能維持正常且不送分析事件。

## 驗證計畫

### 本機與建置

- 執行完整 lint。
- 執行 GitHub Pages 靜態正式建置。
- 確認輸出包含 HTML、JavaScript、CSS、音樂、OG 圖與 favicon。
- 掃描靜態輸出，不得含 GitHub 權杖、環境密碼或問卷測試資料。

### 發布後瀏覽器驗證

至少以桌面與行動版寬度驗證：

- 首頁視覺、導覽及四欄／單欄響應式規則
- 問卷完成一次並產生推薦結果
- 台中行情與方法畫面
- 音樂播放控制及瀏覽器阻擋自動播放時的互動備援
- 所有本機資源回傳成功，外部政府與房仲連結正確
- HTTPS 正常、無 mixed content、主控台無未處理錯誤

### GA4 後續驗證

- 沒有評估 ID時不載入 Google tag。
- 未選擇及拒絕分析時不出現 GA 收集請求。
- 同意後僅出現白名單頁面與事件。
- 依序切換主要畫面，DebugView 中每次只出現一筆正確的虛擬 `page_view`。
- 檢查送出參數，不含任何問卷答案或推薦內容。

## 完成條件

- `https://watah-ai.github.io/` 可公開開啟。
- GitHub Actions 可由 `main` 分支穩定重建與發布。
- 既有網站功能與響應式設計無退化。
- GitHub 儲存庫及靜態輸出不含秘密或使用者資料。
- GA4 在尚未取得評估 ID 前保持關閉；取得 ID 後仍需明確同意才追蹤。
- 使用者已知並接受 GitHub Pages 無法完整提供自訂 HTTP 安全回應標頭的限制。
