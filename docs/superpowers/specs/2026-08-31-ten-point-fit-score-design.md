# 適配度十分制顯示設計

## 目標

將推薦結果的適配度由 100 分制改為使用者較容易理解的 10 分制，降低總分被誤認為成功率、準確率或購屋保證的風險，同時保留既有推薦排序精度。

## 計算與資料

- 內部五項原始分數、權重正規化、貢獻值及總分繼續使用 0–100 尺度。
- Hard Gate、排序、推薦原因、主要犧牲與可信度 A／B 完全不變。
- 只在結果頁顯示時將分數除以 10，並四捨五入至一位小數。
- 不改變 `Recommendation`、`ScorePart` 或 sessionStorage 的資料格式。

## 顯示方式

- 推薦卡主分數由例如 `92` 改為 `9.2 / 10`。
- 適配度驗算的五個細項同步改為十分制，例如：
  - `100` 顯示為 `10.0`
  - `96.8` 顯示為 `9.7`
  - `78` 顯示為 `7.8`
- 長條圖寬度仍使用內部 0–100 分數，因此視覺比例不變。
- 區塊標題由「適配度驗算」調整為「適配度評分」。
- 補充說明：「10 分為相對適配程度，不代表成功率、房屋品質或購屋保證。」

## 可信度

可信度 A／B 繼續表示同類成交樣本量：30 筆以上為 A，低於 30 筆為 B。可信度不是適配分數，不轉換為十分制。

## 邊界與格式

- 0 分顯示為 `0.0`。
- 100 分顯示為 `10.0`，不得顯示超過 `10.0`。
- 一律保留一位小數，避免 `10`、`9.2` 混用造成視覺不一致。
- `/ 10` 在主分數旁清楚可見，但字級低於主要數字。

## 驗證

- 內部總分 92 顯示為 `9.2 / 10`。
- 細項 100、96.8、78 分別顯示為 `10.0`、`9.7`、`7.8`。
- 長條圖寬度、推薦排序與 Top 5 順序在改版前後相同。
- 可信度 A／B、Hard Gate 與推薦內容不變。
- 桌面版與 390px 手機版不發生分數換行或溢出。
- 執行 lint、TypeScript 與 GitHub Pages 靜態建置。
