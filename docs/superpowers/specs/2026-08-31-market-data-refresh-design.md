# 台中房市資料更新與期間自動化設計

## 目標

將網站重新核對至臺中市政府目前最新完整發布的 2026 年第一、第二季買賣案件資料，並移除介面中手動寫死的「2026 上半年／2026 H1」。網站必須清楚區分「政府資料涵蓋期間」與「即時市場行情」，不得暗示資料更新到尚未完整發布的月份。

## 資料來源與範圍

- 來源維持政府資料開放平臺的「臺中市不動產實價登錄資訊－110 年後買賣案件」。
- 目前最新完整資源為 2026-01-01 至 2026-03-31、2026-04-01 至 2026-06-30 兩個檔案；合併後資料涵蓋期間為 2026-01-01 至 2026-06-30。
- 不採用內政部每十日發布的「本期批次檔」混入第三季，因單一期次不等於 7 月至今的完整累積資料，混用會使月份涵蓋不完整。
- 重新下載 Q1、Q2 官方檔案後，以既有清理規則重新彙整；若數據未改版，成交筆數與統計值應維持一致。

## 方案比較與決策

1. **完整季度資料＋期間自動化（採用）**：資料完整、來源一致、可重現；缺點是更新頻率為每季。
2. **混入最新十日批次**：看似較新，但無法保證第三季每個期間都完整，會造成樣本偏差，因此不採用。
3. **串接售屋平台開價**：即時性較高，但開價不是成交價，且涉及第三方授權與介接，不納入本次更新。

## 資料處理

- 彙整程式由輸入檔名的民國年與季度推導資料起訖日；若檔名不符合規則，立即停止並顯示明確錯誤，不猜測日期。
- 輸出 metadata 增加結構化的 `coverageStart`、`coverageEnd` 與供介面使用的期間標籤。
- 保留既有篩選：住家用途、四種常見住宅型態、1 至 5 房，以及總價、單價、面積合理範圍。
- 保留同一「行政區＋建物型態＋房數」至少 12 筆才進入推薦池的門檻。
- 不改動預算、Hard Gate、通勤級距、生活機能分數與排序邏輯。

## 介面呈現

- 首頁特點列、結果頁說明、行情頁英文眉題均改由 metadata 的期間標籤產生。
- 方法頁新增或調整資料說明，明確顯示涵蓋期間與「非即時待售行情」限制。
- 介面維持既有視覺、音樂、自動播放備援、單一捲動、問卷、推薦、GA 同意機制與隱私設定。
- 不增加第三方售屋平台追蹤或任何個資收集。

## 驗證標準

- 官方 Q1、Q2 檔案可成功彙整，metadata 期間為 2026-01-01 至 2026-06-30。
- 行情行政區數、推薦房型樣本及總筆數通過一致性檢查，並說明任何與現版差異。
- 全站不再存在寫死的 `2026上半年`、`2026 年上半年` 或 `2026 H1` 使用者介面文字。
- 推薦計算測試、lint、GitHub Pages 靜態建置均成功。
- 以桌面與行動寬度檢查首頁、行情、方法與至少一組分析結果；既有音樂、單一捲動與 GA 同意前不載入分析標籤的行為保持正常。
- 推送 `main` 後確認 GitHub Pages 工作流程成功，公開網址內容與本次版本一致。

## 未來更新方式

下一季官方完整資料發布後，加入新季度 CSV，以相同彙整指令重建資料；網站期間文字會自動更新，不再逐頁修改年份。每次發布前仍需進行資料筆數、行政區、異常值、建置與瀏覽器檢查。
